À propos

Transit Pulse est une preuve de concept : un pipeline d'agents IA qui fonctionne seul, 24 heures sur 24, sur des données publiques réelles, pour quelques dollars par mois. Lausanne d'abord ; le canton de Vaud ensuite.

Architecture

Le code, les données agrégées et le journal vivent dans un dépôt GitHub public. Chaque exécution réussie ajoute un commit, et Cloudflare Pages republie le site.

Méthode

  • Périmètre : tous les arrêts dont le nom commence par « Lausanne » (gare, métro, bus tl, bateaux), tous exploitants confondus.
  • À l'heure : moins de 3 minutes de retard, comme la ponctualité clients en Suisse. Le départ est utilisé s'il a été mesuré, sinon l'arrivée.
  • Mesuré seulement : seuls les horaires de statut « réel » comptent ; les estimations et prévisions sont exclues. Les retards de plus de 5 heures sont traités comme des erreurs de données.
  • Suppressions : passages annoncés comme supprimés dans le fichier officiel.
  • Aucune cause inventée : le bulletin ne cite une perturbation que si elle figure dans le flux officiel, sans affirmer qu'elle explique les chiffres.

Garde-fous

  • Deux contrôles indépendants avant publication : un agent relit chaque phrase, du code vérifie chaque chiffre.
  • Jusqu'à deux corrections automatiques ; au troisième refus, rien n'est publié et une alerte e-mail part.
  • Plafond de dépense de 10 $ par mois sur l'espace de travail de l'API, alerte à 5 $.
  • Clés d'API uniquement dans les secrets GitHub, jamais dans le code.
  • Quota du flux de perturbations protégé par un compteur (8 appels prévus sur 48 autorisés).
  • Site statique sans cookie, sans script, sans ressource externe ; non indexé par les moteurs de recherche pendant la phase pilote.

Sources

Données ouvertes de la plateforme suisse des données de mobilité : fichier quotidien des horaires réels (Ist-Daten) et flux des perturbations (SIRI-SX). Réutilisation autorisée avec mention de la source.
